# 東京大学合気道気錬会 ホームページ(kirenkai.github.io)

このリポジトリは、気錬会ホームページのすべてのファイルを保管している場所です。
GitHub(ギットハブ)にファイルを置くと、そのままホームページとして公開されます。

> **これまで(Cyberduck でサーバにアップロード)から、GitHub に変更しました。**
> Cyberduck やサーバの ID・パスワードは、もう使いません。
> 担当者が直した内容は、**管理者(OB)が確認してから公開**されます(間違いで公開されるのを防ぐためです)。担当者は、自分用の「作業用ブランチ」まで送れば OK です。

## 1. はじめに

### 1-1. 言葉の説明

| 言葉 | 意味 |
| --- | --- |
| **GitHub** | ファイルをインターネット上に保管するサービス。ここに置いたファイルが、そのままホームページになります。 |
| **リポジトリ** | GitHub 上の「プロジェクト用フォルダ」のこと。このページがそれです。 |
| **クローン(Clone)** | GitHub 上のファイルを、自分のパソコンにコピーすること。最初の1回だけ行います。 |
| **コミット(Commit)** | 「ここまで直しました」と、変更を記録すること。 |
| **プッシュ(Push)** | 自分のパソコンで直した内容を、GitHub に送ること。**これでホームページが更新されます。** |
| **プル(Pull)** | GitHub にある最新の内容を、自分のパソコンに取り込むこと。 |
| **HTML** | ページに書く文章や写真の配置を決めるファイル(拡張子 `.html`)。ほとんどの修正はここだけです。 |
| **CSS** | 文字の大きさ・色・配置など、見た目を決めるファイル(拡張子 `.css`)。 |

### 1-2. ファイルの構成

```
kirenkai.github.io/
├── index.html          ← トップページ(ネットで検索したときに最初に出るページ)
├── about.html          ← 気錬会について
├── schedule.html       ← 稽古日程
├── faq.html            ← よくある質問
├── contact.html        ← お問い合わせ
├── link.html           ← 関連リンク
├── international.html  ← FOR INTERNATIONAL STUDENTS
├── template.html       ← 新しいページを作るときのひな形(公開用ではありません)
├── css/                ← 見た目の設定(style.css など)
├── js/                 ← 動きの設定。基本的に触らなくて大丈夫です
├── images/             ← 写真・画像を入れる場所
└── README.md           ← いま読んでいるこのファイル
```

- ふだん直すのは、基本的に **`.html` ファイルだけ**です。
- `index.html` は特別なファイルで、ホームページの入り口になります。名前を変えたり消したりしないでください。

### 1-3. 必要なもの

- パソコン(Windows でも Mac でも可)
- インターネットにつながる環境
- GitHub のアカウント(無料。作り方は次の章)
- 以下の無料ソフト(インストール方法は次の章)
  - **GitHub Desktop**(GitHub とファイルをやりとりするソフト)
  - **Visual Studio Code(VS Code)**(ファイルを編集するソフト)

## 2. 最初の準備(1回だけ)

### 2-1. GitHub のアカウントを作る

1. <https://github.com> を開き、「Sign up」からアカウントを作ります(メールアドレスが必要です)。
2. **二要素認証(2FA)を設定してください。** アカウントを乗っ取られないための設定です(右上のアイコン → Settings → Password and authentication)。
3. 作ったら、**ユーザー名を管理者(OB)に伝えてください。** このホームページを直せる人として追加してもらいます(追加されるまでは、変更を送れません)。
4. 招待のメールが届いたら、メール内の「Accept invitation」を押します。


### 2-2. ソフトのインストール

1. **GitHub Desktop**: <https://desktop.github.com> からダウンロードしてインストールします。
   起動したら「Sign in to GitHub.com」から、2-1 で作ったアカウントでログインします。
2. **VS Code**: <https://code.visualstudio.com> からダウンロードしてインストールします。

### 2-3. ホームページのファイルを自分のパソコンにコピーする(クローン)

1. GitHub Desktop を開きます。
2. 上のメニューの「File」→「Clone repository...」を選びます。
3. 「GitHub.com」の一覧から **`kirenkai/kirenkai.github.io`** を選びます。
   (一覧にないときは「URL」タブに `kirenkai/kirenkai.github.io` と入力します)
4. 保存先(Local path)を確認して、「Clone」を押します。
5. 完了すると、パソコンにホームページのフォルダができます。
   GitHub Desktop の上のほうにある「Show in Finder」(Windows は「Show in Explorer」)で、そのフォルダを開けます。

これで準備は終わりです。次回からは、この章はやらなくて大丈夫です。

## 3. 更新の流れ(毎回これをやる)

担当者は、**直接はホームページを書き換えられません。** 次の流れで進めます。

1. 自分用の「作業用ブランチ」を作る(下書き用のコピーのようなものです)
2. その中で直して、保存して、確認する
3. 作業用ブランチを GitHub に送って(Push)、管理者(OB)に連絡する
4. 管理者が内容を確認して、公開する

> こうすることで、間違った変更がいきなり公開されることがありません。何度でもやり直せるので、安心して進めてください。
> **担当者が「プルリクエスト」を作る必要はありません。** 管理者に連絡するだけで OK です。

### 手順1: 最新の状態にする

1. GitHub Desktop を開きます。
2. 左上の「Current Repository」が `kirenkai.github.io` になっていることを確認します。
3. 上の真ん中の「Current Branch」が **`main`** になっていることを確認します(違うときは、クリックして `main` を選びます)。
4. 上のほうの「**Fetch origin**」を押します。「**Pull origin**」に変わったら、それも押します。

> 作業を始める前に、必ず行ってください。

### 手順2: 作業用ブランチを作る

1. 「Current Branch」をクリック → 「**New Branch**」を押します。
2. 名前を入力します。**半角英数字とハイフンだけ**にします。
   例: `2026-04-faq`、`2026-04-schedule`(「いつ・何を直すか」がわかる名前にします)
3. 「Create Branch」を押します。

> 以降の作業は、すべてこのブランチの中で行います。`main` のまま直さないでください(`main` には送れません)。

### 手順3: ファイルを編集する

1. GitHub Desktop の「Open in Visual Studio Code」を押すと、VS Code でフォルダ全体が開きます。
   (出ないときは、「Show in Finder」でフォルダを開き、直したいファイルを右クリック → 「このアプリケーションで開く」→ VS Code)
2. 左の一覧から直したいファイル(例: `faq.html`)をクリックして、文章を直します。
3. 直したら **保存**します(Mac: `Cmd` + `S` / Windows: `Ctrl` + `S`)。
   保存を忘れると、変更が反映されません。

具体的な直し方は、[4. よくある修正のやり方](#4-よくある修正のやり方) と [5. HTML の説明](#5-htmlの説明) を見てください。

### 手順4: 自分のパソコンで見た目を確認する

1. フォルダの中の `index.html` を、ダブルクリックで開きます(ブラウザで開かれます)。
2. 直したページをメニューから開いて、意図どおりに表示されているか確認します。
3. 直したらブラウザの更新ボタン(再読み込み)を押すと、最新の状態で見られます。
4. **スマートフォンの幅でも確認します。** ブラウザの幅を狭くすると、スマホ表示になります。

> この段階では、まだ公開されていません。パソコンの中だけで確認しています。

### 手順5: 変更を記録する(コミット)

1. GitHub Desktop に戻ります。左側に、直したファイルの一覧が出ています。
   意図したファイルだけが並んでいるか確認してください。
2. 左下の「Summary」の欄に、何を直したかを短く書きます。
   例:「稽古日程を2026年度版に更新」「新歓用Xのリンクを変更」
3. 「**Commit to (ブランチ名)**」ボタンを押します。

### 手順6: 作業用ブランチを GitHub に送る(プッシュ)

1. 上のほうにある「**Publish branch**」(2回目以降は「**Push origin**」)を押します。

> ここでは、まだ公開されません。作業用ブランチが GitHub に送られただけです。

### 手順7: 管理者に連絡する

1. 管理者(OB)に、**作業用ブランチの名前**(手順2で付けた名前)と、直した内容を連絡します。
   例:「`2026-04-faq` ブランチに、よくある質問の更新を送りました。確認をお願いします」
2. 管理者から修正の依頼が来たら、手順3に戻って直し、手順5〜6をもう一度行います。

### 手順8: 管理者が確認して公開する

管理者が内容を確認して、問題がなければ公開します。担当者がやることはありません。

### 手順9: 公開されたか確認する

1. 管理者から公開の連絡が来たら、**1〜2分ほど待ちます**(公開の反映に少し時間がかかります)。
2. ブラウザで、ホームページを開いて確認します。
   <https://kirenkai.github.io>
3. 変更が見えないときは、ブラウザで強制再読み込みします(Mac: `Cmd` + `Shift` + `R` / Windows: `Ctrl` + `Shift` + `R`)。

### 手順10: 片付ける(次の作業のために)

1. GitHub Desktop の「Current Branch」から `main` を選びます。
2. 「**Pull origin**」を押して、最新の状態にします。
3. 使い終わった作業用ブランチは、「Branch」→「Delete」で消して構いません。

### まとめ(流れだけ見たいとき)

```
main で Pull origin(最新にする)
        ↓
New Branch(作業用ブランチを作る)
        ↓
VS Code で編集して保存
        ↓
index.html をブラウザで開いて確認
        ↓
Summary を書いて Commit
        ↓
Publish branch
        ↓
管理者にブランチ名を連絡
        ↓
管理者が確認して公開 → 1〜2分待ってホームページで確認
        ↓
main に戻って Pull origin
```

## 4. よくある修正のやり方

毎年の更新は、基本的に次の3つで足ります。

1. **`contact.html`**: 新歓用の X(Twitter)と、新歓用メールアドレスの変更
2. **`about.html`**: 写真の変更
3. **`faq.html`**: 質問や回答の変更

### 4-1. 文章を直す

1. 直したいページの `.html` を VS Code で開きます。
2. `<div id="custom-card">` から `</div>` の間が、ページの本文です。ここの文章を直します。
3. 保存して、[手順3](#手順3-自分のパソコンで見た目を確認する) 以降に進みます。

### 4-2. 写真を差し替える・追加する

1. 使いたい写真を、フォルダの `images/` に入れます。
   (VS Code の左の一覧にドラッグ&ドロップするか、エクスプローラー/Finder でコピーします)
2. HTML の写真の部分を、次のように書きます。

   ```html
   <img src="images/写真のファイル名.jpg" alt="写真の説明">
   ```

3. `images/` の中にフォルダを作って整理した場合は、`images/フォルダ名/写真のファイル名.jpg` と書きます。
4. **ファイル名の大文字・小文字、拡張子(`.jpg` など)まで、そのまま書いてください。** 違うと表示されません。
5. 写真はできるだけ小さいサイズにしてください(1枚あたり 1〜2MB 以下が目安)。大きいとページの表示が遅くなります。

### 4-3. 新しいページを作る

1. `template.html` をコピーして、新しい名前にします(例: `newpage.html`)。
   (VS Code の左の一覧で右クリック → Copy → Paste、またはフォルダ上でコピー)
2. 開いて、`<title>` の中の名前を変えます。
3. `<div id="custom-card">` の中に本文を書きます。
4. 他のページからリンクするには、メニュー(`<nav id="drawer">` の中の `<li>`)に1行追加します。
   **メニューはページごとに書いてあるので、全ページに同じ行を追加してください。**

   ```html
   <li><a href="newpage.html">ページの名前</a></li>
   ```

## 5. HTMLの説明

### 5-1. 基本のルール

- ほとんどの命令は `<xx> ... </xx>` という形で書きます。
  `<xx>` が「xx という設定のはじまり」、`</xx>` が「xx という設定のおわり」を表します。
  (閉じる側には `/` が付きます)
- 命令の中に別の命令を入れることができます(入れ子)。
- エディタの見た目を整える自動整形機能を使うと、エラーになることがあります。困ったら `template.html` から該当部分をコピーして貼り付けてください。
- `<!-- ... -->` で囲んだ部分は、メモ書きです。ページには表示されません(CSS では `/* ... */` がメモ書きです)。

### 5-2. 直すところは主に2か所

| 場所 | 意味 |
| --- | --- |
| `<title> ... </title>` | ブラウザのタブに出るサイト名。`template.html` から新しいページを作るときは、必ず名前を変えます。 |
| `<div id="custom-card"> ... </div>` | ページの本文。ここがいちばんよく直すところです。 |

> **フッター(ページ最下部)の著作権表示(Copyright)は、デザインを作った人の署名なので、触らないでください。**

### 5-3. よく使う命令

| やりたいこと | 書き方 |
| --- | --- |
| 改行 | `<br>` (エディタ上で見やすくするための普通の改行は、ページには反映されません) |
| リンク | `<a href="リンク先のURL">表示する名前</a>` |
| 画像 | `<img src="images/ファイル名.jpg" alt="説明">` |
| 他のサイトをページ内に埋め込む | `<iframe src="URL"></iframe>` |
| 見出し(大) | `<m2>見出し</m2>` |
| 見出し(中) | `<m3>見出し</m3>` |
| 赤字 | `<mr>赤字にしたい文</mr>` |

**メモ**

- 同じページ内の別のファイルへのリンクは、`<a href="about.html">気錬会について</a>` のようにファイル名だけで書きます。
- 画像は「`index.html` のあるフォルダ」を基準にして、`フォルダ名/ファイル名` の順で場所を探します。`images/` の中にあるなら、`images/` から書き始めます。
- `<iframe>` に追加の設定をしたいときは、`<iframe src="URL" 設定名="値"></iframe>` のように書き足します。設定が多いときは、CSS のほうに `iframe { ... }` として書くと、すべての `iframe` に反映されます。

### 5-4. CSS の設定を割り当てる

CSS で `A` という名前の設定を作ったとき、その設定を使いたい部分を `<A> ... </A>` で囲みます。
(例: `m1`、`m2` など、`css/style.css` に書いてあります)

## 6. CSSの説明

`css/` フォルダの中のファイルは、文字の大きさ・色・配置など、見た目の細かい設定です。
各項目には、日本語でメモ(`/* ... */`)が書いてあります。まずそれを読んでください。

| ファイル | 内容 |
| --- | --- |
| `css/style.css` | 全体の見た目(ヘッダー、本文、文字、スマホ用の設定など) |
| `css/animation.css` | ハンバーガーメニュー(三本線のメニュー)の動き |
| `css/inview.css` | ページを開いたときの動き(現在は空) |

### 6-1. 基本の形

「A という要素の、B という項目を C にする」という命令は、次の形です。

```css
A {
    B: C;
}
```

項目が複数あるときは、続けて書きます。

```css
A {
    B: C;
    D: E;
}
```

### 6-2. 条件をつける

「画面の幅が 768px 以下のとき(スマホ・タブレット)だけ」のように、条件をつけて設定を変えられます。

```css
@media screen and (max-width: 768px) {
    A {
        B: C;
        D: E;
    }
}
```

### 6-3. 同じ要素の一部だけ別の設定にする

`A.G` と書くと、「A のうち、G という名前をつけたものだけ」の設定になります。

```css
A.G {
    B: C;
}
```

このとき、HTML 側の対象箇所も `<A>` から `<A class="G">` に変更してください。

### 6-4. 書く順番に注意

- 上の行から順に読み込まれ、**同じ要素の同じ項目に対して設定が複数あるときは、下に書いたものが優先**されます。
- 同じ要素の同じ項目でも、上のように条件(`@media`)をつけて、画面の幅ごとに設定を分けられます。

各項目(`font-size`、`padding` など)の意味は、インターネットで調べてください。

### 6-5. JavaScript(`js` フォルダ)について

`js/` フォルダの中のファイルは、ページの動きに関する設定です。**基本的に触らなくて大丈夫です。**
触ってしまって表示や動きがおかしくなったときは、[7-1](#7-1-直したらおかしくなった-まだ-commit-していない) の方法で元に戻してください。

## 7. 困ったとき

### 7-1. 直したらおかしくなった(まだ Commit していない)

GitHub Desktop の左側の一覧で、元に戻したいファイルを右クリック → 「**Discard changes**」を選ぶと、前回の状態に戻ります。
(戻すと、そのファイルの未保存の変更は消えます)

### 7-2. 公開してしまってからおかしいことに気づいた

GitHub は、過去の変更をすべて記録しています。以前のような「魚拓フォルダ」は不要です。
元に戻すのは、管理者(OB)が行います。**気づいたら、すぐに管理者に連絡してください。**

### 7-3. 「Push」や「Publish branch」が押せない・エラーが出る

- 「Current Branch」が `main` のままだと、変更を送れません。作業用ブランチを作って、そちらで作業してください(変更は、ブランチを作るときに持ち越せます)。
- 「Fetch origin」を押して最新にしてから、もう一度試します。
- 「権限がありません」のような内容のときは、[2-1](#2-1-githubのアカウントを作る) の追加がされていない可能性があります。管理者(OB)に連絡してください。
- それでも出る場合は、**エラーの文面をそのまま管理者や前任者に伝えてください。**

### 7-4. 変更が反映されない

- 1〜2分待ってから、強制再読み込み(Mac: `Cmd` + `Shift` + `R` / Windows: `Ctrl` + `Shift` + `R`)してください。
- GitHub のリポジトリのページ(<https://github.com/kirenkai/kirenkai.github.io>)を開き、自分のコミットが見えるか確認します。見えなければ、Push が終わっていません。

### 7-5. 写真が表示されない

- ファイルが `images/` に入っているか確認します。
- HTML に書いたファイル名と、実際のファイル名が(大文字・小文字、拡張子まで)一致しているか確認します。
- ファイル名に日本語やスペースが入っていると、うまくいかないことがあります。英数字にするのがおすすめです。

### 7-6. どうしてもうまくいかない

変更前のファイルから、うまくいっていたところまでで保存し、そこからやり直してください。
詳しいことは、インターネットで調べるか、前任者に聞いてください。

## 8. 守ってほしいこと

- **パスワードや個人情報を、このリポジトリに書かないでください。**
  このリポジトリは公開されており、**誰でも中身を見られます。** 過去の記録(History)にも残るので、一度書くと消すのは大変です。

- **`main` を直接直さず、必ず作業用ブランチで作業してください。**
- **知らない人からのプルリクエストや Issue(連絡)には、反応しないでください。** 開いたり、承認したりしません。気になるものは管理者に連絡してください。

- 作業の最初に必ず Pull、終わったら作業用ブランチを Push して管理者に連絡してください。
